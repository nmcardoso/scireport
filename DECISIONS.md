| 2026-10-09 | Bare strings canonicalise to `text` with `format: plain`; `null` and NaN become a missing `number` (`value: null`); infinities are an error; strings that look like dates stay `text`. | Plain is the safe default: markdown by default would silently mangle `_` and `*` in identifiers. A date must be said (`kind: date`). The builder maps NaN to missing because that is how Python code says missing. | S1 (proposed, not gated) |
| 2026-10-09 | An object with a `kind` member is always an envelope; one without is a `mapping` whose entries keep their order. | Removes the ambiguity between a mapping and an envelope; a mapping with an entry called `kind` is written in full. | S1 |
| 2026-10-09 | Asset references need `path`, `sha256` and `bytes` in sealed bundles (ZIP). In directories and single files (hand-authoring) the hash and size may be left out, or the reference written as the bare path, and the reader computes them from disk; `pack` writes the completed manifest. Done through a resolver callable in the pydantic validation context. | A person writing YAML cannot compute sha256. The resolver keeps the spec models free of file access. | S1 |
| 2026-10-09 | Asset paths: `assets/<attachments|figures|images|tables|text>/<file>`, segments `[A-Za-z0-9][A-Za-z0-9._-]*`, at most 180 characters, no Windows reserved names, no trailing dot, no two paths equal when case-folded. The writer names files after keys (`<key>.parquet`, `<key>.data.parquet`, ...). | Unpacks identically on Linux, macOS and Windows. The folder-per-kind layout of ADR-0001 is kept. | S1 |
| 2026-10-09 | A key may not also be the dotted prefix of another key (`E102`). | Templates reach values through `data.a.b.c` chains (plan D5), so `a.b` cannot be both a value and a namespace. | S1 |
| 2026-10-09 | Manifest writing: `values` sorted by key; every field is written except optional ones that are None (defaults are explicit); canonical JSON with two-space indent, UTF-8, trailing newline; no clock anywhere (`meta.date` and `provenance` times are never filled automatically); `provenance.writer` records `scireport <version>`. | Same content gives the same bytes regardless of insertion order; a later change of a default cannot change how a stored bundle reads. | S1 |
| 2026-10-09 | ZIP: sorted entries, 1980-01-01 timestamps, creator system 3, mode 0644, no comment; STORED for png, jpg, jpeg, gif, webp, pdf, parquet, zip, gz, zst, xz; DEFLATE level 9 for the rest. Caveat: the compressed bytes of DEFLATED entries depend on the zlib build, so byte identity is guaranteed for one Python and zlib; the sha256 in the manifest never depends on it. Compat fixtures are committed bytes that tests only read. | ADR-0001 asks for byte-reproducible ZIPs but compression of text is worth the size; the caveat is recorded so a cross-platform byte comparison is not promised. | S1 |
| 2026-10-09 | Limits: 1 GiB total uncompressed (`--max-size`, MiB), 10,000 ZIP entries, 32 MiB manifest. ZIP entries that are symbolic links, encrypted, case-insensitively duplicated or unsafe are rejected (`E407`); directory bundles refuse symbolic links (`E404`). | ADR-0001: zip-slip rejection and a size cap. Reports hold summaries, so the defaults are generous but finite. | S1 |
| 2026-10-09 | Manifest YAML is read with YAML 1.2 core scalars (only `true`/`false` are booleans, `yes`/`12:30`/`007`/dates stay strings), no aliases and no duplicate keys; JSON rejects duplicate members and NaN/Infinity. YAML is accepted only for directories and single files. | ADR-0001 criticises YAML typing ambiguity; this is the mitigation. Aliases can multiply a small file into a huge structure. | S1 |
| 2026-10-09 | Writes are atomic (a hidden sibling name, then rename) and use the umask; an existing destination needs `--force`, and a non-empty directory is replaced only if it already looks like a bundle. | An interrupted write never leaves half a bundle; `--force` cannot delete an unrelated directory. | S1 |
| 2026-10-09 | The `render` block already carries `template`, `layout`, `formats`, `pdf_engine`, `latex_engine`, `markup_engine`, `math_renderer` and `options`; all optional, None means "decided by the template, layout or command line". | Plan D3, D4, D11 and D12 name these fields; adding them now avoids a spec bump before 1.0 is frozen at S7. | S1 |
| 2026-10-09 | Vocabularies follow MOSAICS: row verdicts `pass|warn|fail`, alert levels `info|warning|error`, status levels `success|warning|partial|failed|running`, flow states `done|reused|skipped|failed|running|pending`, column align `left|right|center|path`. | Keeps the ported components and gzms content one-to-one. | S1 |
| 2026-10-09 | Table: storage format (`parquet` or `csv`) follows the file suffix; verdicts are `row_status` (inline tables) or `row_status_column` (a data column); `overflow_attachment` is the key of an `attachment` value (checked: `E103`, `E202`); the writer records `n_rows`. | One source of truth for the format; works for tables too large to inline. | S1 |
| 2026-10-09 | The frozen JSON Schema describes the canonical manifest (every value an envelope; `values` keys must match the grammar). Bare-JSON shorthand and hash-less asset references are loader conveniences, documented in the schema description. Until v1.0.0 is released the file is regenerated with `make schema`; afterwards the drift test makes any change a break (ADR-0008). | A schema that admits shorthand would accept almost anything and lose its value for agents. | S1 |
| 2026-10-09 | Error codes introduced in S1: E101-E104 keys, E201-E206 kinds and fields, E301-E302 tables, E401-E411 assets and bundles, E501-E503 versions, W402 unreferenced asset (`scireport.errors.CODES`).
